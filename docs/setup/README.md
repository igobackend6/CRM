## Android Requirements

- Android SDK 36.1.0, installed at `%LOCALAPPDATA%\Android\sdk`
- Android licenses accepted (`flutter doctor` reports all accepted)
- JDK: bundled with Android Studio (OpenJDK 21.0.10)
- No Visual Studio / Windows desktop toolchain is required — this project targets Android only in Phase 1 (`flutter create --platforms=android`). iOS support can be added later (`flutter create --platforms=ios .`) without restructuring, per the architecture's platform-agnostic `lib/core` and `lib/services` layers.

## Mobile (`mobile/`) — Local Setup

```bash
cd mobile
flutter pub get
cp env/.env.example env/.env.development
cp env/.env.example env/.env.staging
cp env/.env.example env/.env.production
# edit each env/.env.<flavor> with real Supabase URL + anon key
flutter run --dart-define=FLAVOR=development
```

`env/.env.*` (other than `.env.example`) are git-ignored — every developer creates their own from the template. The app reads `FLAVOR` at build time via `--dart-define` (defaults to `development` if omitted).

## Backend (`backend/`) — Local Setup

```bash
cd backend
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS/Linux
source .venv/bin/activate

pip install -r requirements.txt
cp .env.example .env
# edit .env with real Supabase URL + service-role key (never commit this file)

uvicorn app.main:app --reload
# in another shell:
curl http://localhost:8000/health
```

Run the test suite:

```bash
pytest
```

## Supabase — Local Setup

```bash
cd ..  # repo root
supabase start   # requires Docker Desktop running
```

`supabase/config.toml` was generated by `supabase init`. `supabase/migrations/` is currently empty (no CRM schema yet — that's Phase 2). `supabase/seed.sql` is a placeholder.

## Known Limitation (documented, not hidden)

Local `supabase start` requires Docker Desktop, which was not exercised as part of this Phase 1 pass (no Docker validation was run in this environment). `supabase init`, `config.toml` generation, and the migrations/seed scaffolding were verified directly via the Supabase CLI (`supabase --version` → 2.106.0, `supabase init` completed successfully). Running the local stack end-to-end should be verified by whoever next has a Docker-enabled environment, before Phase 2 schema work begins.
